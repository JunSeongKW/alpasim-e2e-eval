# drivable_area 실패 분석 (2026-08-27)

`human_penalty_filter` 를 끈 라벨을 만들다가, **기록된 사람 궤적조차
`drivable_area_compliance` 를 대량으로 실패한다**는 것을 발견해 원인을 추적한 기록.

결론부터: **폴리곤이 편측 25 cm 부족한 것이 실패의 63 %p 를 만든다.**
차량 치수도, 교차로 누락도, 오프셋 버그도 아니었다.

---

## 1. 발견 경위

filter ON/OFF 라벨을 대조하니 필터가 개입한 토큰이 많았다. 필터는 **사람이 그
지표에서 0 점일 때만** 개입하므로, 곧 사람이 실패했다는 뜻이다.

| 지표 | 사람이 실패한 토큰 (5,007 개 중) |
|---|---:|
| drivable_area_compliance | 1,907 (**38.1 %**) |
| lane_keeping | 1,372 (27.4 %) |
| driving_direction_compliance | 353 (7.1 %) |
| time_to_collision_within_bound | 132 (2.6 %) |
| no_at_fault_collisions | 99 (2.0 %) |

실제 주행 데이터에서 사람이 열 번 중 네 번 도로를 벗어났을 리 없다 → 데이터 문제.

---

## 2. 기각된 가설들

같은 실수를 반복하지 않도록 **틀린 것도 남긴다.**

### ❌ "교차로 폴리곤이 없다"
처음 시각화에서 교차로가 빈 공간으로 보였으나, **`ROADBLOCK` 만 그렸기 때문**이었다.
`INTERSECTION` 레이어는 정상 존재하고 교차로를 잘 덮는다 (맵당 4~10 개).

### ❌ "차량 치수가 잘못 들어갔다"
채점기는 `get_pacifica_parameters()` (5.176 × 2.297 m) 를 쓴다. NuRec 로그의
`vehicle_name` 은 `'nurec'` 뿐이고 맵 pkl `matched_ego` 에도 치수가 없다.
차폭을 바꿔가며 사람 궤적 실패율을 재보면:

| 차량 치수 | 실패율 |
|---|---:|
| Pacifica 5.18×2.30 (현재) | 73.3 % |
| width 2.10 | 72.0 % |
| width 1.95 | 71.3 % |
| width 1.80 | 68.7 % |
| 4.80×1.90 | 70.0 % |

**차폭을 22 % 줄여도 4.6 %p 변화뿐.** 치수는 원인이 아니다.

### ❌ "rear-axle 오프셋 버그"
채점기는 올바르다 — `pdm_array_representation.py:210`:
```python
ego_centers = states[..., StateIndex.POINT] + rear_axle_to_center * [cos, sin]
```
**틀린 쪽은 이 분석의 초기 시각화였다.** 박스를 rear axle 중심으로 그려 1.461 m
뒤로 밀린 상태로 측정했다. 그림을 다시 그릴 때 반드시 오프셋을 넣을 것.

### ❌ "LANE 을 drivable 에 포함시키면 넓어진다"
채점기는 `LANE` 을 drivable 판정에서 제외한다 (다중차선 판정에만 씀). 그런데
면적을 재보면 **`LANE ⊆ ROADBLOCK` 이라 증가분이 정확히 0 m² (0.000 %)** 다.
포함시켜도 아무 효과가 없다.

### ❌ "원본에 넓은 drivable annotation 이 있는데 안 쓴다"
맵 pkl 의 `polygons` 키에 `drivable_space` 가 **존재하지만 비어 있다.**
맵 60 개 합계: crosswalk 418, intersection_area 317, road_island 222,
gore_area 145, **drivable_space 0, buffer_zone 0**.
`DRIVABLE_AREA` / `CARPARK_AREA` 레이어가 0 개인 이유. 원본 릴리스에 없다.

## 3. 확인된 원인 — 폴리곤 폭 부족

채점 영역은 `ROADBLOCK | INTERSECTION | DRIVABLE_AREA | CARPARK_AREA` 인데
(`pdm_scorer.py::_calculate_ego_area`), NuRec 은 뒤의 둘이 0 개다. 즉
**roadblock 폭이 곧 판정 경계**가 되고 여유 면이 전혀 없다.

union 을 편측 d 미터 버퍼링했을 때 사람 궤적 실패율 (표본 200 토큰, 오프셋 정상 적용):

| 버퍼 | 실패율 | 개선 |
|---:|---:|---:|
| 0.00 m | 78.0 % | — |
| **0.25 m** | **15.0 %** | **-63.0 %p** |
| 0.50 m | 13.0 % | -65.0 %p |
| 0.75 m | 12.0 % | -66.0 %p |
| 1.00 m | 12.0 % | -66.0 %p |
| 2.00 m | 10.5 % | -67.5 %p |
| 3.00 m | 10.0 % | -68.0 %p |

**25 cm 에서 대부분 해결되고 그 뒤로는 평평하다.** 25 cm 는 차선 표시선 두께나
폴리곤 이산화 오차 수준 — 사람이 도로를 벗어난 게 아니라 폴리곤이 그만큼 모자랐다.

**3 m 를 넣어도 10 % 는 남는다.** 이건 버퍼로 해결되지 않는 별개 문제로,
ego 위치 자체가 폴리곤 밖인 경우다 (무작위 120 토큰 중 2.5 %, 이탈 p90 12 m).
맵↔궤적 정합 오차로 보인다.

```
78 %  =  63 %p (폴리곤 25 cm 부족)  +  ~5 %p (0.25~3 m)  +  10 % (정합 오차)
```

## 4. 학습에 미치는 영향

filter OFF 라벨에서 필터 개입 토큰이 어떻게 되는지 (표본 435 개):

| 구간 | 비율 | GT ↔ 최고점 |
|---|---:|---:|
| 생존 0 개 (**무신호 = 무해**) | 39.8 % | — |
| 생존 1~40 개 | 5.7 % | 4.82 m |
| 생존 41~200 개 | 5.3 % | 6.10 m |
| **생존 200 개 초과** | **49.2 %** | **4.48 m** |

양쪽 다 유효 신호가 있는 263 토큰만 직접 비교:
```
GT↔최고점   filter ON   중앙값 4.08 m   p75 5.76 m
            filter OFF  중앙값 4.13 m   p75 8.74 m
```

**중앙값은 동등하고 꼬리만 나빠진다.** 즉 filter OFF 라벨은 쓸 수 있다:
- 49 % 는 정상 신호가 새로 생긴다 (filter ON 에서는 4096 개 전부 1.0 이라 무신호였다)
- 40 % 는 전부 0 이라 학습에 기여하지 않는다 — 깨진 토큰이 자동 배제되는 셈
- 11 % 만 후보가 적어 흔들리지만 파국적이지 않다

> ⚠️ 초기에 "filter OFF 면 최고점이 GT 에서 10.8 m 로 멀어진다"고 결론냈으나
> **측정 오류였다.** 생존 0 개인 배열에 `argmax` 를 쓰면 무조건 index 0 (임의의
> vocab 항목)이 나오는데 그걸 최고점으로 집계했다. 구간을 나누면 위 표가 된다.

### 생존 0 개인 토큰은 왜 그런가
4096 개 중 하나도 안 되는 건 "어려운 상황"으로 설명되지 않는다. 전 후보가 0 인
지표를 세어보면:

| 지표 | 비율 |
|---|---:|
| **drivable_area_compliance** | **91.5 %** |
| driving_direction_compliance | 7.3 % |
| no_at_fault_collisions | 2.2 % |
| traffic_light_compliance | 0 % |

모든 후보가 ego 위치에서 출발하므로, **출발점이 폴리곤 밖이면 첫 스텝부터 전부
실패**한다. 궤적 모양과 무관하게 4096 개가 동시에 0 이 된다.

## 5. 개선 방향

**① roadblock 버퍼링 (권장)** — 편측 **0.25~0.50 m**. 0.5 m 를 넘으면 얻는 게
거의 없으면서 인도·중앙분리대 침범 궤적까지 통과시킨다. 적용 지점 둘:
- `metric_cache` 생성 시 `PDMDrivableMap` 폴리곤에 `buffer()` — 캐시 재생성 필요
- scorer 내부 조회 결과에 반영 — 캐시 재생성 불필요, 채점 경로 수정

**② 맵↔궤적 정합 오차 조사** — 버퍼로 안 되는 10 %. ego 위치가 폴리곤에서
10 m 넘게 떨어진 케이스. 특정 clip 에 몰려 있는지 확인하면 그 clip 만 고칠 수 있다.

**③ 사람 궤적 스윕으로 `DRIVABLE_AREA` 생성** — clip 별로 사람 footprint 합집합을
레이어로 추가. 정의상 안전한 하한선이지만 사람이 안 간 곳은 여전히 빈다.
